# 手机 ↔ PC 结果传输协议

PC 端在局域网里起一个 HTTP 服务（默认 8737），手机端打完流把结果推过来。
协议只有两个接口，都用 JSON，UTF-8 编码。

---

## 一、探活

```
GET /api/v1/ping
```

手机端「扫描电脑」用这个：往局域网每个 IP 的 8737 端口发一次，200 就是有 PC 端在。

响应：

```json
{
  "ok": true,
  "schema": "wifitput.result/1",
  "app": "WiFiTputPC",
  "time": "2026-10-30 18:06:15",
  "modes": ["wifi", "hotspot", "p2p", "pc"]
}
```

---

## 二、推结果

```
POST /api/v1/results
Content-Type: application/json; charset=utf-8
```

请求体是一个「结果包」（bundle）。成功返回 200：

```json
{
  "ok": true,
  "saved_to": "D:\\...\\输出\\20261030_180615_wifi_tput_WiFi",
  "files": [{"name": "逐秒明细.csv", "bytes": 3893},
            {"name": "汇总.json", "bytes": 48929},
            {"name": "测试报告.md", "bytes": 4433}]
}
```

### 错误码

| 码 | 含义 |
| --- | --- |
| 400 | 请求体不完整，或不是合法的 UTF-8 JSON |
| 411 | 缺 `Content-Length` |
| 413 | 请求体超过 32 MB |
| 422 | JSON 合法但结构不合法（见下文字段校验） |
| 500 | PC 端落盘失败 |
| 503 | 接收服务未就绪 |

---

## 三、结果包结构

```jsonc
{
  "schema": "wifitput.result/1",       // 必填；版本不符 PC 端直接拒收
  "app":     {"name": "...", "version": "1.0", "package": "com.wifitput.android"},
  "run":     {"id": "...", "mode": "wifi|hotspot|p2p|pc",
              "started_at": "YYYY-MM-DD HH:MM:SS", "finished_at": "..."},
  "meta":    {"items": ["wifi_tput"], "duration": 30, "streams": 4,
              "reverse": false, "port": 5201, "udp_bw": "",
              // 连PC 额外字段（旧包可没有）：
              "test_kind": "pc_tput", "duration_per_direction": 60,
              "tools": {"client": "iperf 3.22", "server": "iperf 3.22"},
              "direction": "both", "bandwidth": "tcp_unlimited",
              "location": {"preset": "近点", "distance_m": 3}, "long_run": false},
  "devices": [ DeviceInfo, ... ],      // 至少一台，和 CLI 版 probe() 的字段一致
  "results": [ TestResult, ... ],      // 每项测试一条
  "records": [ Record, ... ],          // 逐秒明细，CSV 直接由它生成
  "screen":  null | { ... },           // 亮灭屏对比，没有就 null
  "notes":   ["..."]                   // 给人看的补充说明，会进报告第七节
  // 连PC 额外顶层字段（旧包可没有）：
  // "ping": {"method":"udp","probes":10,"lost":0,"loss_pct":0.0,
  //          "avg_ms":3.2,"min_ms":2.1,"max_ms":6.4}
  // "telemetry": [{"t":1.0,"rssi":-48,"cpu_pct":23.1,...}]
  // "telemetry_summary": {"rssi_avg":-49,"cpu_avg":25.0,"disconnects":0,
  //                       "samples":120,"mcs":null,"snr_db":null}
  // "server": {"label":"PC · LAB","ip":"10.0.0.2","iperf_port":5201,
  //            "http_port":8737,"version":"iperf 3.22"}
}
```

### Record（18 字段，顺序即 CSV 列序）

`t` `elapsed` `test` `kind` `stream` `start` `end` `transfer` `unit` `rate`
`rate_unit` `retr` `jitter` `lost` `total` `lost_pct` `role` `raw`

- `test` 取 `tcp_up` / `tcp_down` / `udp_up` / `udp_down` / `long_run` /
  `screen_on` / `screen_off`。
- `stream` 是 `#4` 这种单流标签或 `SUM`。
- `rate_unit` 原样保留 iperf3 的单位（`bits/sec` / `Mbits/sec` / `Gbits/sec`），
  PC 端会自己换算，**不要**预先转成 Mbits。
- UDP 的 sender 行 `lost` / `lost_pct` 留空（iperf3 那行本来就是 0/0）。

### TestResult

```jsonc
{
  "test_id": "tcp_up",
  "name": "WiFi 吞吐量（TCP 正向）",
  "kind": "TCP",
  "params": {"duration": 30, "streams": 4, "reverse": false},
  "sender":   {"rate": 276.0, "unit": "Mbits/sec"},
  "receiver": {"rate": 271.0, "unit": "Mbits/sec"},
  "ok": true,
  "error": "",
  "records_n": 240
}
```

缺字段不会报错（PC 端按默认值兜），但 `test_id` 最好给全，否则报告里的子节标题会
退回成测试项编号。

### DeviceInfo

和 `WiFi吞吐量测试工具` 的 `devinfo.probe()` 返回完全一致，键包括：
`serial` `state` `model` `brand` `device` `android` `sdk` `abi` `hardware`
`fingerprint` `screen` `battery{level,temp_c}` `wifi{connected,ssid,band,channel,
rssi,link_tx_mbps,link_rx_mbps,phy,freq_mhz,addrs,ifaces}` `hotspot{on,ssid,iface,
addrs,freq_mhz,clients}` `default_route` `ram_mb` `cores` `storage_free_gb`
`uptime_s` `iperf{version,path}`。

## 四、最小可用示例

```bash
curl -X POST http://10.216.9.198:8737/api/v1/results \
     -H "Content-Type: application/json; charset=utf-8" \
     --data-binary @结果包.json
```

PC 端界面的「模拟发送」按钮就是用本机生成的示例包走这条路径，
可以拿来对照着写手机端。

## 五、连PC 的发现与空闲探测（UDP 8738）

PC 工具「本机服务端」页会监听 **UDP 8738**，手机在同一个局域网内自动发现它：

| 请求 | 应答 | 说明 |
| --- | --- | --- |
| `WIFITPUT/DISCOVER/1` | 以 `WIFITPUT/HERE/1` 开头的应答（见下方格式） | 手机扫描 PC |
| `WIFITPUT/PING/1` + nonce | `WIFITPUT/PONG/1` + nonce | 空闲 ping 的丢包/延迟 |

```
WIFITPUT/HERE/1|PC · 主机名|<iperf端口>|<iperf版本>|<HTTP端口>|PC
WIFITPUT/PONG/1|<nonce>
```

- HERE 前三个字段与手机端原有发现协议兼容；第 4/5/6 个字段是新增的版本、HTTP 接收端口、类型。
- 手机 App 的发现应答发 `kind=PHONE`；「连PC」页只列 `kind=PC` 的应答。
- 空闲 ping 优先用 UDP 探测（Windows 防火墙默认常拦 ICMP）；UDP 全丢时手机回退到
  TCP 握手到 iperf3 端口，报告里的 `ping.method` 会写 `tcp`。
