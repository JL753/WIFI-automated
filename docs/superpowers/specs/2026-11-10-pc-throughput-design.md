# 「连PC」单机吞吐测试 · 设计文档

日期：2026-11-10
状态：已实现（2026-11-10），实现偏差见 §16

## 1. 意图与为什么

现有工具测「手机 ↔ 手机」的 WiFi 吞吐，必须两个人配合。苹果开发者模式里的
Run Throughput Test 可以**一台手机直接测**，输出四项：ping 丢包、闲置 ping 延迟、
下载速度、上传速度。我们希望在本工具里加一个类似但更适合 WiFi 研发的版本：

- 一台手机，对着**同一局域网里的一台 PC**测，而不是公网服务器。
- 这样测到的不是互联网出口，而是「手机 ↔ AP ↔ PC」这条链路，结果不会被公网带宽卡住，
  RSSI、频段、信道、近/中/远点这些才有意义。
- PC 端由现有 `PC端工具` 一键启动 iperf3 服务端，并自动被手机发现。
- 原有的双机 WiFi / 热点 / P2P 模式保留，不做破坏性改动。
- 所有「开始打流」按钮文案统一改成「开始测试」。

## 2. 目标 / 非目标 / 反目标

### 目标

1. Android 新增第四个页签 **「连PC」**：扫描/选择同网段 PC → 空闲 ping → 下载 →
   上传，两个方向各跑满设定时长；结果卡展示**ping 丢包、闲置 ping 延迟、下载、上传**。
2. PC 工具新增 **「本机服务端」** 页：一键启停 iperf3 3.22 服务端，显示本机 IP/端口/状态；
   在 UDP 8738 上同时负责**发现应答**和**空闲探测**，让手机自动找到它。
3. 测试结果进入现有结果包和 `report.py` 报告链路，新增标准报告所需字段：
   工具/版本、方向、带宽设置、频宽/信道/频点、距离/位置、时长、重传率、RSSI/SNR、
   MCS、断流次数、CPU 占用、结论；并给出**进出服务器的平均结果**。
4. 单机结果卡和历史详情能分享摘要、导出 CSV；结果自动上传给 PC 出报告。
5. 保留双机三模式；共享现有结果卡/统计/历史/深色/外观能力。

### 非目标

- 不使用苹果的服务器，也不做公网测速模式（本轮明确改为同网段 PC）。
- 不引入 root 或厂商私有 API；MCS/SNR 拿不到的字段标「不可用」，不伪造。
- 不做 `iperf3 --bidir` 同时双向；按「先下载、再上传，各跑满时长」执行。
- 不替代 PC 端报告渲染；手机端是结果卡 + CSV + 摘要。
- 不做真机验证（用户明确暂不需要）。

### 反目标

- 把「连PC」结果当成互联网宽带或公网路径的结果。
- 为了凑字段编造 MCS/SNR/频宽。
- 改坏现有三模式的结果包、报告或历史兼容性。
- 为了长稳把手机内存/存储写爆，或让 24h 测试把 App 卡死。

## 3. 已确认的决定

| 事项 | 决定 |
| --- | --- |
| 名称 | 页签叫「连PC」，不叫「单机」 |
| 服务器 | 实验室同一网段 PC，由 PC 工具一键启动 iperf3 |
| 方向 | 下载 + 上传，**每个方向都跑满设定时长**（总时长约为 2×） |
| 空闲 ping | PC 的 UDP 8738 探测器（Windows 防火墙常拦 ICMP）；报告注明「UDP 探测」，可另做 ICMP 尝试/回退 |
| PC 发现 | 复用现有 `WIFITPUT/DISCOVER/1` / `HERE` 协议；HERE 增加版本、HTTP 接收端口等字段 |
| 报告 | 扩展现有结果包 + `report.py`，保持旧结果包可读 |
| 按钮 | 所有模式「开始打流」→「开始测试」 |
| MCS/SNR | 普通 Android 不可用，报告标注；RSSI、频段/信道/频点、协商速率、重传率、断流、CPU 采集 |

## 4. 组件与数据流

```
PC端工具
  ├─ 收结果（现有 HTTP 8737）
  └─ 本机服务端（新）
       ├─ iperf3.exe -s -p 5201（3.22，随包/同级目录）
       └─ UDP 8738：发现 ASK/HERE + PING/PONG
                    ▲
手机「连PC」页        │ 局域网
  ├─ 扫描 PC（UDP 8738）→ 地址/版本/接收端口自动填
  ├─ 空闲 ping（UDP PING/PONG，10 次）
  ├─ 下载：iperf3 -c PC -p 5201 -R -t D -P N --get-server-output
  ├─ 上传：iperf3 -c PC -p 5201    -t D -P N --get-server-output
  ├─ 遥测：RSSI/频段/信道/协商/CPU/断流（1s 或长稳 5s 采样）
  └─ 结果包 → POST 到 PC:8737 → report.py → CSV/JSON/MD
```

## 5. PC 工具「本机服务端」

新增 `pcapp/pcserver.py` + `pcapp/ui/tab_server.py`，主窗口加第四个页签。

### 服务端

- 定位 iperf3：
  1. `PC端工具/bin/win/iperf3.exe`（新增，随包一份）；
  2. `../WiFi吞吐量测试工具/bin/win/iperf3.exe`；
  3. `../WiFiTput/bin/win/iperf3.exe`。
  都找不到时页面给出明确错误与放置路径。
- 启动 `iperf3.exe -s -p 5201 --forceflush`，stdout/stderr 落到日志文件并实时读回界面。
- 停止：terminate → 等待 → kill；退出页面/关闭工具自动停止。
- 显示本机所有 IPv4（复用 `receiver.local_ips()`）、端口、iperf3 版本、运行状态。
- 端口冲突（5201 被占）给出中文提示，可在设置里改端口。

### UDP 8738

一个后台线程、一个 UDP socket，兼容两种消息：

| 请求 | 应答 | 用途 |
| --- | --- | --- |
| `WIFITPUT/DISCOVER/1` | `WIFITPUT/HERE/1\|PC · <主机名>\|<iperf_port>\|<iperf版本>\|<http_port>` | 手机自动发现 |
| `WIFITPUT/PING/1\|<nonce>` | `WIFITPUT/PONG/1\|<nonce>` | 空闲探测 RTT/丢包 |

- HERE 前三个字段保持旧格式兼容；第 4、5 个字段新增，旧手机忽略。
- 手机端 `Discovery.Peer` 增加 `version`、`httpPort`、`kind`（"PC"）字段。
- Windows 防火墙：页面明确提示放行 **TCP 5201（或自定义端口）** 与 **UDP 8738**；
  提供「打开防火墙设置」按钮，不自动提权改规则。

### 与「收结果」的关系

- HTTP 接收服务 8737 继续独立运行；本机服务端页只负责 iperf3 + UDP。
- 手机完成测试后把结果包 POST 到 HERE 里给出的 HTTP 端口（默认 8737），
  PC 的收结果/出报告流程完全复用。

## 6. Android「连PC」页

新增 `ui/PcPanel.java` + `ui/PcSession.java` + `ui/PcResultCard.java`，不复用
TabPanel 的模式分支，避免把已稳定的三页继续撑大。

### 6.1 页签与外壳

- `MainActivity` 页签数组改为 `WiFi / 热点 / P2P / 连PC`。
- 抽出 `PanelHost` 接口（`setStatusSink/isBusy/isClientRun/runStartMs/modeTitle/
  stopAll/refreshHotspot/persistSettings`），TabPanel 与 PcPanel 都实现；
  MainActivity 的面板列表按接口持有，扫码回调只对 TabPanel 转型处理。
- 沿用控制台式布局：顶部状态胶囊 → 连接卡 → 数据卡 → 「⚙ 设置」抽屉 → 日志条；
  设置抽屉沿用可拖拽底部面板。

### 6.2 连接卡（准备状态）

- 大标题「连PC」，状态胶囊「未连接 / 已找到 PC / 测试中 / 完成」。
- 「PC 服务器」一行：扫描到的 PC 标签 + IP:端口（如 `PC · LAB-01  10.66.2.20:5201`）。
- 主按钮：
  - 没选 PC：「扫描 PC」；
  - 已选：「开始测试」。
- 副按钮：「手工填写」「重新扫描」。
- 参数摘要 chips：`TCP · 4 流 · 60 秒 · 下载+上传`、位置（近点/中场/远点）、距离。
- 扫描使用现有 `Discovery.scan(3000)`；结果弹窗列出同一网段所有应答者，
  PC 条目带版本号；若同时有手机服务端，也能看到并选择（不是只能连 PC）。

### 6.3 测试流程

`PcSession` 在后台线程依次执行：

1. **空闲 ping**：向 PC 的 UDP 8738 发 10 个 `PING`（200ms 间隔），
   记录成功数、丢包率、平均/最小/最大 RTT。无应答时尝试 TCP 连接 5201 三次，
   报告标注「TCP 握手延迟（UDP 探测不可用）」。
2. **下载**：`Iperf.runClient(..., reverse=true)`，PC→手机，时长 D，流数 N。
3. **上传**：`Iperf.runClient(..., reverse=false)`，手机→PC，时长 D，流数 N。
4. **遥测**：从开始到结束每 1s（长稳 5s）采样。
5. 组装结果包（两次 result + ping + telemetry + 元数据）→ 上传 PC → 保存历史。

- 每个方向都跑满 D；界面明确显示「下载 D 秒 + 上传 D 秒，预计 2D」。
- 方向固定「双向（先下载后上传）」；参数里记录 `direction=both`。
- 使用现有 `Iperf.runClient` 的 `--get-server-output`，取回 PC 侧速率作为
  「进出服务器的平均结果」；PC 侧版本来自发现应答。
- 任一方向失败：保留已完成方向的结果，结论标注失败原因；不伪造另一方向。

### 6.4 结果卡（完成后）

`PcResultCard` 展示四项主指标：

```
下载  xxx Mb/s     上传  xxx Mb/s
ping 丢包  x.x%     闲置 ping  xx ms
```

下面是标准字段摘要：工具（手机 iperf3 版本 / PC 版本）、方向、带宽设置（TCP 不限速）、
时长（每方向）、流数、位置/距离、频段/信道/频点、重传率、RSSI、CPU、断流次数；
MCS/SNR/频宽显示「不可用」或用户手填值（见 §7）。

动作：**再测一次 / 连测 3 次 / 分享摘要 / 导出 CSV**；结果自动上传 PC；
历史记录保留完整日志、结果包和遥测。

### 6.5 设置抽屉

- PC 地址/iperf 端口、HTTP 接收端口（默认从发现结果带出）。
- 时长：60 秒（默认）/ 2 小时 / 8 小时 / 24 小时 / 自定义；显示预计总时长 2×。
- 并发流、采样间隔（长稳预设自动用 5 秒）。
- 位置：近点/中场/远点 + 距离（米）+ 标签。
- 「UDP 丢包拐点」（可选测试项，见 §8）。
- 自动上传 PC 开关（默认开）。

### 6.6 日志与控制台

- 沿用日志条 + 全屏日志；下载/上传阶段切换时写一行阶段日志。
- 顶栏全局状态显示「连PC · 测试中 00:07」「下载/上传阶段」。
- 下载和上传各画一条实时曲线（同一张图，阶段切换时清空并在标题注明方向）。

## 7. 遥测与可行性边界

新增 `core/Telemetry.java`，在测试期间按采样间隔记录：

| 字段 | 来源 | 可行性 |
| --- | --- | --- |
| RSSI / 频段 / 频点 / 信道 / 802.11 标准 | `WifiManager` / `WifiInfo` | 可用 |
| 协商速率 TX/RX | `WifiInfo` | 可用（系统上报，非实测） |
| RAT（WLAN/LTE/5G） | `ConnectivityManager` / `TelephonyManager` | 可用（本轮主要 WLAN） |
| 重传率 | iperf3 TCP retr / 传输量 | 可用（TCP） |
| 断流次数 | 网络丢失事件 + iperf3 0 速率区间 | 可用（计数） |
| CPU 占用 | `/proc/stat` 总 CPU + `/proc/self/stat` 本 App | 可用 |
| 电量/温度 | `Dev` 现有能力 | 可用（快照/采样） |
| MCS | 无公开 API | **不可用，标 N/A** |
| SNR | 无公开 API | **不可用，标 N/A** |
| 频宽（20/40/80/160） | `WifiInfo` 不直接提供 | **不可用；允许设置里手填** |

- 遥测数组写入结果包（长稳按 5s 采样并限制条数），同时给出一份汇总：
  RSSI 均值/最低、CPU 均值/最高、断流次数、重传率、采样点数。
- 明确在报告里写「MCS/SNR 为 Android 公共 API 不可得」，避免使用者误以为是设备不支持。

## 8. UDP 丢包拐点（可选测试项）

标准报告要求「TCP 不限速；UDP 逐步加压看丢包拐点」。本轮把它做成连PC页的
**可选测试项**，不阻塞主流程：

- 速率阶梯可配（默认 10/20/50/100/200/500/1000 Mb/s），每档 10 秒，
  只测下载方向（PC→手机，`-u -R -b XM`）。
- 每档记录发送速率、接收速率、丢包率、抖动；当丢包率 > 1% 连续两档停止。
- 结果：拐点速率（最后一个丢包 ≤1% 的档位）+ 完整阶梯表。
- 报告新增「UDP 拐点」章节；主报告「带宽设置」写「TCP 不限速 + UDP 阶梯」或仅其一。

## 9. 长稳（2h / 8h / 24h）

- 每个方向都跑满设定时长，所以 24h 预设实际约 48h；界面在开始前必须显示预计总时长和警告。
- 长稳预设自动把采样间隔调成 5 秒（可改）；结果包/遥测条数按 5s 控制。
- 实时曲线在长稳时只保留最近窗口（RateChart 的 MAX_POINTS 提升/降采样）；
  长稳结果包只保留 SUM 区间行 + 5 秒遥测，不保留单流明细（见 §15.6）。
- 手机必须插电、避免过热；前台服务/唤醒锁沿用 KeepAlive；PC 端服务端不得休眠。
- 断流/网络切换会记录到遥测；24h 结果包可能很大，历史保留策略按现有 KEEP=50 条，
  文档提示长稳后及时导出/清理。

### 10.2 report.py（同步 `_vendor_report.py`）

新增 `TEST_NAMES`：`pc_down`/`pc_up`；`ITEM_NAMES`：`pc_tput`。
Markdown 报告新增/扩展：

1. **结论摘要**：下载/上传平均速率、ping 丢包、闲置延迟、是否断流/卡顿；
   一句话稳定性结论（如「下载稳定，上传出现 3 次 0 速率，重传 1.2%」）。
2. **测试参数**：工具与版本、方向、带宽设置、每方向时长/流数/采样、位置/距离、
   RAT/频段/信道/频点/频宽（不可用标 N/A）。
3. **设备与服务器**：手机设备信息 + PC 服务器标签/IP/version。
4. **测试结果**：下载、上传两节，各自发送端/接收端/平均/最低/最高/重传/停滞；
   PC 侧（服务器进出）平均值单列。
5. **链路与稳定性**：ping、RSSI/CPU/断流/重传率汇总；MCS/SNR N/A 说明。
6. **UDP 拐点**（若执行）：阶梯表与拐点。
7. **异常与提示**：长稳发热/断流/失败方向等。

旧结果包/旧报告不受影响；同一份 `report.py` 供手机端 PC 工具和命令行共用。

## 11. CSV 导出

- 连PC结果导出两份逐秒明细（下载/上传）或一个带 `direction` 列的文件；
  列与现有 `逐秒明细.csv` 一致，另加方向/阶段列（向后兼容）。
- 服务端侧行（server output）只用于报告平均，不混入逐秒明细，沿用现有约定。

## 12. 兼容与约束

- 现有双机三模式、历史、深色/外观、CSV、对比功能不改行为。
- 现有 `Discovery` 的 ASK/HERE 前三个字段不变；新增字段旧端忽略。
- 现有 `Iperf.runClient`/`Record`/`Stats`/`report.py` 尽量复用。
- PC 工具 PySide6 依赖不变；iperf3.exe 随包/同级目录。
- 不新增 Android 依赖；不引入 root。
- 不真机验证；以编译、PC 端逻辑测试和布局预览验收。

## 13. 验收标准

1. PC 工具「本机服务端」一键启动，手机「连PC」扫描能看到 `PC · 主机名 · iperf 3.22`，
   自动填 IP/端口。
2. 点击「开始测试」：空闲 ping → 下载（满 D）→ 上传（满 D），结果卡出现四项主指标；
   每个方向都有平均/最低/最高/重传/停滞。
3. 结果自动上传 PC，PC 出报告；报告含标准字段、进出服务器平均、遥测、结论；
   MCS/SNR 标 N/A。
4. 断开 PC 服务端/拔网线：方向失败有明确提示，不伪造数据。
5. 现有 WiFi/热点/P2P 三模式回归正常；「开始测试」文案生效。
6. 深色模式、历史对比、CSV、标签在新页同样可用。
7. 2h/8h/24h 预设能开始并在界面显示预计总时长；长稳采样按 5s。
8. 未做真机验证时，Android 编译通过、PC 端服务端/发现/探测逻辑可独立自测。

## 15. 构建审查后的补充决定

以下 5 项已定案；长稳保真度见 §15.6（待用户确认）。

### 15.1 模式与 schema

- `run.mode = "pc"`；PC 端 `protocol.MODES` 增加 `"pc"`；`Bundle.itemId()` 返回 `pc_tput`。
- 旧结果包、旧报告保持可读；**连PC 新包要求更新后的 PC 工具**（旧 PC 工具会因未知 mode 返回 422，
  客户端提示升级）。不把连PC 冒充成 wifi，避免历史/目录/报告误标。
- 历史列表、对比、结果目录使用 pc 模式标识。

### 15.2 双向数据模型

- 结果包 `results` 包含 `pc_down`、`pc_up` 两条，各自有独立的 records/stats。
- 结果卡主数字：**下载 = 手机接收端**，**上传 = 手机发送端**（与苹果口径一致）；
  PC 侧（服务器进出）平均在报告里单列，不混进主数字。
- 「占协商速率」：下载用手机 RX、上传用手机 TX 分别计算；PC 侧不参与。
- 历史详情、CSV、对比、连测 3 次都按两方向处理：下载/上传分别展示与统计；
  连测的中位数/最低/最高也分别给两方向。
- 新增 `Stats.ofBundle(json, index)`（保留无 index 的旧版本）；`CsvExport` 对连PC 导出一个
  16 列 CSV，`测试` 列用 `pc_down` / `pc_up` 区分方向（见 §16 的实现偏差）。
- 对比：连PC 记录按「下载对下载、上传对上传」比较；`sameParams` 包含时长/流数/协议/间隔/方向。

### 15.3 上传目标与接收服务

- 连PC 使用独立的 `pc_upload_host` / `pc_upload_port`（从发现结果带出），
  **不覆盖**其它三模式共用的 `pc_host` / `pc_port`。
- PC 工具「本机服务端」启动时：若 HTTP 接收服务未运行，自动尝试启动；
  只有实际监听时才在 HERE 里广播 `http_port`；接收服务不可用时页面明确提示，
  不静默广播 8737。
- 手机端若连PC 的 HTTP 端口不可达：结果仍保存在本机历史，日志提示「已保存，未上传」，
  可稍后重传。

### 15.4 发现与设备分类

- HERE 增加 `kind` 字段：
  `WIFITPUT/HERE/1|label|iperf_port|version|http_port|kind`。
  PC 工具发 `PC`；手机 App 的发现应答发 `PHONE`；旧端忽略多余字段（前三个字段保持兼容）。
- 连PC 扫描只列 `kind=PC`（或带 http_port/version 的新式 PC 应答）；
  没找到 PC 时提示先在 PC 工具启动「本机服务端」。
- 双机三模式仍可看到 PC 条目（它就是一个 iperf3 服务端），但连PC 页不把手机服务端当 PC：
  手机没有 PING/HTTP 接收能力，选中也不走 PC 流程。

### 15.5 指标定义

- 重传：保留原始 `retr_sum`；新增 `retr_per_mb = retr_sum / 传输量(MB)`；
  `retr_pct_est = retr_sum / (retr_sum + transfer_bytes/1460) × 100`，
  明确标注「估算，假设 MSS 1460B」。不把它叫丢包率。
- 断流：`stall_episodes` = 连续速率为 0 的采样区间合并为一次；
  `network_loss_events` = 测试期间默认网络/WiFi 从有到无的切换次数。
  报告里「断流次数」用 stall_episodes，「网络断开」用 network_loss_events，两者都列。
- MCS/SNR/频宽：不可用字段写 N/A；频宽允许设置里手填，报告标注「手动」。
- ping 方法：UDP 探测优先；无应答时 TCP 握手回退，报告写清 `method`。

### 15.6 长稳数据保真度（已确认：接受建议）

- **60 秒短测**：保留每流逐秒完整记录。
- **2h / 8h / 24h 长稳**：只保留 **每秒 SUM 区间行 + 5 秒遥测**；不保留单流明细。
  报告仍能看平均/最低/最高、断流、重传、RSSI/CPU 趋势，但不再声称有每流明细。
- PC 接收上限从 32 MB 提高到 **64 MB**（按实测再调）；手机历史增加**按体积清理**
  （例如总量上限 200 MB，超了删最旧的，仍保留 KEEP=50 的上限）。
- 长稳包只写 SUM 行（不写每流明细）；现有契约仍同时写顶层 `records` 和
  `results[].records`，行数已受控；旧报告对短测不受影响。
- 24h 预设每方向跑满，实际约 **48h**；开始前显示预计总时长、耗电/发热/PC 不得休眠的警告。
- 长稳失败/断流时保留已完成区间的数据，结论明确标注不完整，不补造数据。

## 16. 实现偏差（2026-11-10 交付时）

- CSV 没有拆成下载/上传两个文件：连PC 导出一个 16 列 CSV，`测试` 列用
  `pc_down`/`pc_up` 区分方向；PC 报告同样。
- 连PC 结果卡没有做「连测 3 次」：保留「再测一次 / 分享摘要 / 导出 CSV / 加标签」；
  连测可以后续加。
- 历史详情的连PC 记录新增一张四项摘要卡（下载/上传/ping/PC 服务器），
  原结果卡和对比仍按第一条（下载）结果展示；任意两条对比的下载对下载、上传对上传
  还没有做成双列。
- PC 工具「本机服务端」在切换页签时保持运行，只有退出整个工具才停（否则手机测试中切到
  「出报告」会把服务端停掉）。
- `iperf3.exe` 连同 Cygwin DLL 一起放进 `PC端工具/bin/win/`，不依赖同级目录。
- 长稳结果包仍按现有契约同时写顶层 `records` 和 `results[].records`，但只写 SUM 行，
  行数受控；没有改 schema 写入路径。
- 连PC 的遥测、ping、server 信息进入报告新章节；MCS/SNR/频宽固定 N/A。
