# WiFi / 热点 吞吐量测试工具 · 使用说明

这是一套在 Windows 上跑的测试工具：用两根数据线连两台安卓手机，让其中一台做服务端、一台做客户端，用 iperf3 打真实流量，测出**真实空口吞吐**，并把结果整理成 CSV / JSON / Markdown / 原始输出四份文件。

整目录拷走就能用，不需要装任何第三方 Python 包。

---

## 一、这个工具能做什么

| # | 测试项 | id | 需要的手机 | 说明 |
|---|---|---|---|---|
| 1 | WiFi 吞吐量测试 | `wifi_tput` | 2 台 | 两台连同一个 WiFi，测 TCP 上行与下行 |
| 2 | 热点吞吐量测试 | `hotspot_tput` | 2 台 | 一台开热点、另一台连上去测 |
| 3 | 亮灭屏对比测试 | `screen_cmp` | 2 台 | 亮屏 N 秒 / 灭屏 N 秒交替，对比吞吐差异 |
| 4 | 长稳吞吐测试 | `long_run` | 2 台 | 单次长跑，看速率抖动与重传累积 |
| 5 | UDP 抖动丢包测试 | `udp_qos` | 2 台 | 限速 UDP，看 jitter 与丢包率 |
| 6 | 链路质量快照 | `link_snapshot` | 1 台 | 只采集不测速，出环境基线 |
| 7 | PC 参与的隧道测试 | `pc_tunnel` | 2 台 | PC 当一端走 adb 隧道（**测的是 USB 带宽**） |

可以一次选多项，按上表顺序依次跑。

## 二、准备工作（对方第一次用时照着做）

1. **装 adb**：本工具默认在 `C:\Program Files\ADB\adb.exe` 找 adb；装在别处会自动在 PATH 里找。找不到时工具会明确报出来。
2. **手机开开发者选项 → USB 调试**，插上数据线，在手机弹窗里点「允许」。
3. **两台手机要么连同一个 WiFi，要么一台开热点、另一台连上去**。两台不在同一网段时工具会在自检阶段就拦住并说明原因。
4. 在电脑上执行 `adb devices`，两台都要显示 `device`（不是 `unauthorized` / `offline`）。

> 手机端的 iperf3 **不需要你手动装**：工具会检测 `/data/local/tmp/iperf3`，没有或版本不对就自动从 `bin\iperf3-arm64v8` 推上去并 `chmod 755`。

## 三、怎么运行

### 方式 1：双击（推荐给第一次用的人）

双击 `启动.bat`，进交互菜单：加载后**立刻打印所有已连接设备的详细卡片**，然后按序号选测试项、确认参数、开始。

菜单项：

```
  1  开始测试（先选测试项，再确认参数）
  2  修改参数
  3  重新扫描设备
  4  只看设备信息
  5  链路质量快照（单机，不产生流量）
  0  退出
```

### 方式 2：命令行直跑（推荐给要批量/自动化的人）

```bat
启动.bat list
启动.bat run -i wifi_tput,udp_qos -t 30 -P 4
启动.bat run -i hotspot_tput -t 60 -P 4 --no-reverse -s 16306705AY100050 -c 179402567R000037
```

参数表：

| 参数 | 含义 | 默认 |
|---|---|---|
| `-t` | 每项测试时长（秒） | 30 |
| `-P` | 并发流数 1-16 | 4 |
| `-I` | 采样间隔（秒，1-60），调大能减少逐秒行数 | 1 |
| `-R` / `--no-reverse` | 是否同时做反向 -R 测试 | 开 |
| `-b` | UDP 限速，如 `50M` 或 `auto` | auto |
| `-L` | 长稳测试时长（秒） | 300 |
| `-i` | 测试项 id，逗号分隔 | 交互选 |
| `-s` / `-c` | 服务端 / 客户端序列号 | 交互选 |
| `-O` | 输出目录 | `输出\` |
| `-p` | 服务端口 | 5201 |

参数会被记住：跑完一次后，这次用的时长 / 流数 / 采样间隔 / 反向 / 端口等写进工具根目录的 `配置.json`，下次打开（菜单模式）默认就是这一套。命令行显式传的参数永远优先于记忆值。想回到出厂默认，删掉 `配置.json` 即可。

---

### 方式 3：用打包好的 exe（对方没有 Python 时最省事）

`WiFiTput.exe` 是用 PyInstaller 打出来的单目录程序，**目标机器不需要装 Python**：

```
WiFiTput\
├─ WiFiTput.exe
├─ _internal\        ← 运行时依赖，不能删
├─ bin\              ← 手机端 iperf3 与 PC 端 iperf3，不能删
└─ 输出\             ← 结果目录（首次运行自动创建）
```

用法与 `启动.bat` 完全一致，参数也一模一样：

```bat
WiFiTput.exe
WiFiTput.exe list
WiFiTput.exe run -i wifi_tput -t 30 -P 4 --no-reverse
```

三条硬性注意：

1. **`bin\` 必须和 exe 放在一起**。手机端 iperf3 要推给手机，没法打进 exe 里。缺了会在自检阶段报「本地缺少手机端 iperf3 二进制」并说明该放哪个路径。
2. **`_internal\` 不能删、不能改名**，那是 Python 运行时与标准库。
3. 整个 `WiFiTput\` 文件夹一起拷走，别只拷 `WiFiTput.exe`。

exe 版只有 Python 引擎，没有降级引擎——它本身就是「不需要 Python」的方案。

要自己重新打一次包（改了代码之后），双击工具目录里的 `打包exe.bat`。它会：找 Python → 用 `tools\_buildtools\pyinstaller` 里自带的 PyInstaller 打包 → 把 `bin\` 一并拷到产物旁边 → 清掉中间目录。产物默认落在工具目录的上一级 `WiFiTput\`，也可以自己指定：`打包exe.bat D:\some\where\WiFiTput`。

> 打包需要 PyInstaller。工具目录里已经带了一份（`tools\_buildtools\pyinstaller`，约 6.4 MB），所以离线也能打。这份目录被 `.gitignore` 忽略，不随仓库分发；没有它时 `打包exe.bat` 会提示去 `pip install pyinstaller`。

## 四、运行中能做什么

测速跑起来后，终端会**逐秒滚动**每一秒的数据，同时可以按键打点：

| 键 | 作用 |
|---|---|
| `L` | 标记「此刻亮屏」 |
| `D` | 标记「此刻灭屏」 |
| `M` | 打一个普通标记 |
| `Q` | 提前结束当前这一项测试 |

打点会记进 `汇总.json` 的 `marks` 里，方便你把「灭屏那一秒掉速」和具体时刻对上。

手动亮灭屏的典型用法：只选一个测试项、把 `-t` 设长（比如 300 秒），跑起来后自己按手机电源键亮/灭屏，用 `L`/`D` 打点，事后看 CSV 里哪几秒速率变了。

## 五、怎么读屏幕上的数据

逐秒行长这样：

```
10:33:56 | #4   0-1s         21.8 MB    182.0 Mb/s  retr 0
```

| 字段 | 含义 |
|---|---|
| `10:33:56` | 本机收到这一行的本地时间 |
| `#4` | iperf3 的**流编号**（socket fd），不是线程序号；4 条流实际是 `#4 #6 #8 #10` |
| `[SUM]` | 所有流的合计行 |
| `0-1s` | 统计区间（第 0 秒到第 1 秒） |
| `21.8 MB` | 这一秒传输的数据量 |
| `182.0 Mb/s` | 这一秒的平均速率。单位跟随 iperf3 原样输出：链路上千兆时会写成 `6.9 Gb/s`，别当成 6.9 Mb/s（**÷8 才是 MB/s**） |
| `retr` | TCP 重传次数。持续大于 0 说明空口在丢包 |
| `jitter` | 仅 UDP：抖动毫秒数 |
| `lost` | 仅 UDP：丢失包数 / 总包数（丢包率） |

末尾会出现 `---------- 全程汇总 ----------`，后面两行是全程结果，不是某一秒：

```
#4   全程         118.0 MB    197.0 Mb/s  retr 0  sender
#4   全程         117.0 MB    194.0 Mb/s  retr 0  receiver
```

### 关键：`sender` 和 `receiver` 怎么取

`receiver` **永远是「收数据的那一端」**，会随测试方向变。工具里的视角统一是**客户端手机**：

| 测试 | 命令 | 收数据的是谁 | 读 `receiver` 得到的是 |
|---|---|---|---|
| 正向（无 `-R`） | 客户端发、服务端收 | 服务端 | 客户端 **上行 / TX** |
| 反向（`-R`） | 服务端发、客户端收 | 客户端 | 客户端 **下行 / RX** |

### 服务端地址是怎么取的

跑测试前工具会先打三行自检，第 2 步就是服务端地址：

```
[2/3] 服务端地址 ...
      OK  10.23.160.19（取自 热点地址）
      --  服务端 16306705AY100050 的网卡地址（adb shell ifconfig）：
      --      wlan0  无 IPv4 地址
      --      wlan1  10.23.160.19/24
```

地址来源就是你指定的 `adb shell ifconfig`（工具里也会顺手跑一次 `ip addr` 兜底，两边的结果会合并去重）：

| 行 | 含义 |
|---|---|
| `wlan0` | 手机连别人 WiFi / 热点时用的地址 |
| `wlan1` | 手机自己开热点时用的地址 |
| `无 IPv4 地址` | 这个网卡没启用或没拿到地址 |

取哪个当服务端地址的优先级：**热点地址（wlan1）> wlan0 > 第一个非 lo 地址**。
所以「A 开热点、B 连上去」时，服务端地址一定是 A 的 wlan1，不会误取到蜂窝口的 `rmnet_data*`。

设备卡里也有一行 `网卡 wlan0 10.23.160.23/24   wlan1 --`，加载脚本时就能看到，不用等开跑。

### 报告里的「平均 / 最低 / 最高」怎么来的

报告第四节每项下面都有一行统计，例如：

```
统计：平均 232.0 Mbits/sec，最低 46.2 Mbits/sec，最高 378.0 Mbits/sec，重传合计 1022。
```

- **平均** 取全程汇总行（`0-20s ... sender/receiver`），不是逐秒平均，所以不会因为开头慢被拉低。
- **最低 / 最高** 只统计**合计行（`[SUM]`）**的逐秒速率，不混入单条流，否则多流时会算出「最高 179 而平均 229」这种自相矛盾的数。
- 逐秒速率先按 iperf3 给的**单位换算成 Mbits/sec 再比较**。完全停滞的那一秒 iperf3 打的是 `0.00 bits/sec`，换算后就是 0.0，不会被当成 500 Mb/s。
- 出现 0.0 时统计行会补一句「其中 N 秒完全停滞（0 bit/s），不是采样误差」——**这是真的卡了，不是显示抖动**，长稳测试里最值得看的就是这个。

结论摘要里的百分比是**区间**：`吞吐仅达协商速率的 23%~49%`，前者是最差的一项（通常是下行），后者是最好的一项。只写最差值会和逐项结论打架。
百分比超过 150% 的样本会被排除（说明这段数据没走空口，比如同一台手机 loopback、或两端走的是同一个 AP 的以太回程）。

## 六、输出文件

每次运行在 `输出\` 下建一个 `YYYYmmdd_HHMMSS_<测试项简写>\` 目录（重名自动加 `_2`），里面是：

| 文件 | 内容 | 给谁看 |
|---|---|---|
| `逐秒明细.csv` | 每一秒一行的原始数据（16 列） | 丢进 Excel 画曲线的人 |
| `汇总.json` | 结构化汇总：参数、设备信息、每项结果、亮灭屏对比、打点 | 写脚本做回归对比的人 |
| `测试报告.md` | 六节可读报告（结论摘要 / 测试参数 / 设备信息 / 测试结果 / 亮灭屏对比 / 异常与提示） | 直接发出去看结论的人 |
| `原始输出_<test_id>.txt` | iperf3 的完整原始输出，一字不改 | 要复核原始数据的人 |

CSV 列：`时间, 测试, 类型, 线程, 起, 止, 传输量, 单位, 速率, 速率单位, 重传或数据报, 抖动ms, 丢包, 总包, 丢包率, 方向`。

CSV 用 `utf-8-sig` + CRLF，Excel 直接双击不乱码。

结果目录旁边还会自动生成一个同名的 `.zip`（如 `20261030_154637_wifi_tput.zip`），把上面四个文件按原文件名打进去，方便直接发给别人。zip 打包失败不影响结果文件本身，只会在屏幕上多一行提示。

自己还没跑过、只想先看看报告长什么样，可以直接打开 `输出\示例\两台真机全7项\`，里面是一份两台真机跑完 7 个测试项的完整产物（12 秒级短跑，数字只作样例，不代表真实性能）。

## 七、没有 Python 会怎样

`启动.bat` 按顺序找 Python：

1. PATH 里的 `python`
2. `py -3` 启动器
3. 工具目录下自带的 `python\python.exe`（如果你拷了一个便携版进来）

三条都没有时，自动切到 PowerShell 降级引擎（`tools\fallback\wb_fallback.ps1`）。**降级引擎只覆盖 WiFi / 热点吞吐这两项**，其余测试项不可用，界面上会说明。

> 要完整功能就装 Python 3.8+（python.org 下载时勾选「Add python.exe to PATH」）。工具只用标准库，装完不需要 `pip install` 任何东西。

### 降级引擎能干什么、不能干什么

| 能力 | Python 引擎 | 降级引擎（PowerShell） |
|---|---|---|
| WiFi 吞吐量测试（`wifi_tput`） | 支持 | 支持 |
| 热点吞吐量测试（`hotspot_tput`） | 支持 | 支持 |
| 亮灭屏对比 / 长稳 / UDP 抖动丢包 / 链路快照 / PC 隧道 | 支持 | **不支持**，会打印三段式说明后退出 |
| 设备卡、参数预设、运行中打点 | 支持 | 设备卡与参数预设支持，打点不支持 |
| 输出文件 | CSV + JSON + Markdown + 原始输出 | 同名同格式（16 列 CSV、utf-8-sig、CRLF） |

降级引擎认这些参数（注意：关闭反向是 `--no-reverse`，**不是** `-NoReverse`）：

```
启动.bat list
启动.bat run -i wifi_tput -t 30 -P 4 --no-reverse
启动.bat run -i hotspot_tput -t 30 -P 2 -s <服务端序列号> -c <客户端序列号>
启动.bat --selftest        自检：造一份假数据把 CSV/JSON/MD 写一遍再校验编码和列数
```

降级引擎的文件是 UTF-8 **带 BOM**。这是刻意的——Windows PowerShell 5.1 读无 BOM 脚本会按 GBK 解码，中文全变乱码。不要用编辑器把它「转成无 BOM」。

## 八、常见问题

**Q：报「没有检测到可用设备」**
`adb devices` 里没有 `device` 状态的设备。检查：开发者选项是否开了 USB 调试、数据线是否只充电不通数据、手机弹窗是否点了「允许」。

**Q：报「两台手机不在同一网段或热点没开」**
工具会先 ping 服务端地址，通不过就不跑。让两台连同一个 WiFi，或一台开热点另一台连上去。

**Q：报 `iperf3: error - the server is busy running a test. try again later`**
上一次的服务端没退干净。工具在启动服务端前会 `pkill -9 -f iperf3` 并等 2 秒；如果还报这个，手动在手机上清一次：`adb shell pkill -9 -f iperf3`。

**Q：报告里写「超过协商速率 540 Mbps 的 5889%，说明这段数据没走空口」**
说明这次的流量根本没经过 WiFi 空口——最常见是同一台手机既当服务端又当客户端（loopback，GB/s 级），或者两端接在同一个 AP 的有线回程上。这种数据只能用来验证工具链路通不通，**不能当 WiFi 成绩**。要测真实空口，必须一台开热点/连 WiFi，另一台从空中接入。

**Q：测出来只有几十 Mbps，比 WiFi 标称低很多**
先看报告里的「设备信息」：RSSI 是不是很差、协商速率是多少、是不是 2.4G。空口吞吐通常只有协商速率的 30%~60%，这是正常的。另外熄屏往往比亮屏**更快**（省电策略放松了限制），所以别在亮屏时跑着跑着就判定设备有问题。

**Q：亮灭屏对比里某一轮失败了**
失败轮次会被显式跳过并打印原因，**不会**当 0 计入平均。如果整批都失败，看 `原始输出_screen_on.txt` / `原始输出_screen_off.txt` 里的 iperf3 报错。

**Q：PC 参与的那项为什么标着「测的是 USB 带宽」**
那一项是 PC 当服务端、手机通过 `adb reverse` 走数据线，链路里根本没有 WiFi。它的用途是给你一个「USB 隧道基线」，**不要拿它当 WiFi 成绩**。本机没有无线网卡时，这一项在菜单里会被标注出来。

**Q：能不能同时开两个终端各跑一份**
**不能。** 服务端启动前会 `pkill -9 -f iperf3`，会把另一份正在跑的服务端杀掉，两边都会失败。手机上同一时刻只能有一方在跑 iperf3。

## 十、把工具发给别人

1. 把**整个 `WiFi吞吐量测试工具\` 目录**打包发出去（不要只发 `启动.bat`）。
2. 对方解压到任意路径（路径里有中文和空格都可以）。
3. 对方装好 adb、手机开 USB 调试，双击 `启动.bat`。

对方没有 Python 时有两个选择：让 `启动.bat` 自动落到 PowerShell 降级引擎（只支持 WiFi / 热点吞吐两项），或者直接发 `WiFiTput\` 文件夹给对方（不需要 Python，7 项全支持）。

手机端 iperf3 由工具自动推送，对方不需要额外准备任何东西。
