# WiFiTput · Android App

一个装在手机上的打流（吞吐量测试）App。两台手机装同一个 App，一台「当服务端」、另一台「扫描对端 → 开始打流」，就能测 WiFi / 热点 / P2P 三条链路的真实吞吐。测完可以一键把结果推给 PC 端接收器出报告。

- 打流引擎是 **iperf 3.22**（Termux 动态链接构建），已打进 App，不用另外装 iperf、不用 root。
- 结果格式与 PC 端、命令行工具完全一致，同一份 `report.py` 渲染。
- 三档模式：**WiFi**（两台连同一个路由器/热点）、**热点**（引导到系统设置开热点）、**P2P**（Wi-Fi Direct 点对点，扫码即连）。
- 找对端有三种方式：**扫描对端**（弹窗列出扫到的手机，点一条就填好）、**投屏码**（P2P 页一台出码、另一台扫码，自动组网+自动填地址）、**手工填地址**。

> 想搞清楚「这些数字是怎么测出来的、为什么可信、能测什么不能测什么」，看
> [测试原理与数据说明.md](测试原理与数据说明.md)。

## 安装

两种安装包都在上一级 `APK\` 目录里：

| 文件 | 大小 | 说明 |
| --- | --- | --- |
| `WiFiTput.apk` | 4334768 字节 | release 版，日常用这个 |
| `WiFiTput-debug.apk` | 5039605 字节 | debug 版，带可调试标记，排查问题用 |

```
adb install -r APK\WiFiTput.apk
```

也可以直接把 apk 拷进手机点安装（需要在系统里允许「安装未知来源应用」）。

**注意**：release 版用的是本机的 debug 签名证书（`CN=Android Debug`），不是发布用的正式证书。自己用、装给自己和同事的机器没问题；要上应用商店必须换成正式密钥重新签名。

首次打开会先说明几项权限的用途：位置（读取 WiFi 名称、频段和信号）、相机（扫投屏码）、
附近设备（Android 13+ 搜索 P2P 对端）。选择「稍后」也能手工填地址测速。

## 两台手机怎么测

以 WiFi 模式为例（A 开热点或两台连同一台路由器）：

1. **A**：打开 App → 停在「WiFi」页 → 点「当服务端」。日志出现
   `OK iperf3 已就绪：iperf 3.22 (cJSON 1.7.15)` / `OK 服务端已监听 5201，等对端来打流`。
   同时会起前台服务，锁屏、切后台都不影响。
2. **B**：打开 App → 点「扫描对端」→ 扫 3 秒后**弹出窗口列出扫到的对端**（形如
   `Infinix X6878 · WiFi` / `10.66.2.84:5201`），点一条就自动填好地址并关窗。
   没扫到时弹窗会给三条排查提示（对端没点「当服务端」/ 不在同一网络 / 连在访客网络被隔离）。
3. **B**：按需要调参数（时长 / 并发流 / 采样间隔 / 协议 TCP-UDP / 方向 正向-反向 / 限速），
   可以在「本次标签」里写个位置或场景（可选），点「开始打流」。
4. 跑完日志会出现 `OK 完成，用时 N 秒` + `-- 发送端 xxx Mb/s   接收端 xxx Mb/s`，
   以及 `-- 结果包已生成：N 条逐秒记录`；同时曲线下面弹出**结果卡**，
   给出接收端速率、最低/最高、重传/丢包和一句结论，可以直接「再测一次」「连测 3 次」或「分享」。

打流过程中**两台手机的日志是同步滚的**：A（服务端）那台也会逐秒打出
`12:31:00 | -- #5   15-16s   22.1 MBytes   186 Mb/s`，不用等跑完才看到结果。

参数含义：

- **时长**：单次打流秒数，默认 10。
- **并发流**：iperf3 `-P`，默认 4。
- **采样间隔**：iperf3 `-i`，默认 1 秒。调大（如 3 秒）逐秒行会变少、日志更清爽，
  但统计粒度也变粗；想看清每秒抖动就保持 1。
- **协议**：TCP / UDP。切到 UDP 后「限速」输入框才生效。
- **方向**：正向（本机发）/ 反向（本机收，iperf3 `-R`）。
- **限速**：只对 UDP 有效，例如 `50M`。

## 界面怎么排的

三个页（WiFi / 热点 / P2P）用同一套卡片布局，从上到下依次是：

1. **顶部标题卡**：左边模式名、右边状态胶囊，同一行。胶囊平时是蓝底「空闲」，
   点「当服务端」成功后变绿底「服务端就绪」，出错时变红底；下面一行是模式说明。
2. **这一台干什么**：两个按钮「当服务端」「扫描对端」，下面按当前模式给一句操作建议
   （WiFi 页建议路由器下那台当服务端；热点页建议开热点那台当服务端；P2P 页建议先组网）。
   **「我的投屏码」「扫码直连」只在 P2P 页出现**，WiFi / 热点页没有。
3. **对端地址**（可收起）：对方地址 + 端口。
4. **测试参数**（可收起）：时长 / 并发流 / 采样间隔一行，协议 / 方向 / UDP 限速一行。
5. **系统热点**（仅热点页）或 **投屏直连 + 手动组网（备用）**（仅 P2P 页）。
6. **运行**：最上面是「本次标签」（可选），下面是「开始打流」蓝底主按钮，
   跑起来变「停止」；当服务端时主按钮变灰显示「服务端运行中」，停止走上面的「停止服务端」。
   「重传上次结果」是白底次按钮（注意它是把上一次的结果再发给 PC，不是重测）；
   右边还有「全屏」——日志太多看不清时点它，会弹出一个占屏幕 72% 高的大窗口，
   里面能上下滑，也能「复制」到剪贴板。
   按钮下面依次是**实时速率曲线**、**结果卡**和滚动日志，新行进来时自动跟到底，
   手动往上翻就不打断你。

**可收起的卡片**：「对端地址」「测试参数」右上角有 `收起 ▴` / `展开 ▾`，
点标题行任意位置也能切。收起状态**会记住**——下次打开 App 还是你上次的样子。
想一屏看完就把这两张收起，只留「开始打流」、速率曲线和日志。

**实时速率曲线**：日志上方那块折线图，和股票分时图一个看法——

- 横轴是本次测试的秒数（客户端按「时长」固定好，服务端随对方打多久往后长），纵轴是 **Mb/s**。
- 每秒一个点，多流会自动相加；采样间隔调成 3 秒时，曲线也就是 3 秒一个点。
- 左上角大字是**当前速率**，右边 `▲ +12.3` / `▼ -8.4` 是相对上一个采样点的涨跌
  （默认采样 1 秒就是「比上一秒」；红涨绿跌，箭头也标了方向），下面一行是本次**峰值**。
  曲线下面淡淡的蓝色面积和末端圆点就是「现在」。
- 每次点「开始打流」都会清空重画；当服务端时对方重新发起一轮，也会自动换一条新曲线。
- 结尾那条 `0.00-10.00 sec` 的整段汇总行不会混进曲线，所以不会在末端凭空鼓起一个尖峰。

**结果卡（跑完自动出现）**：曲线下面会出现一张结果卡，把这次测试讲清楚——

- 左上大字是**接收端速率**（反向时是客户端收到的速率）；右边是发送端、最低、最高。
- 中间是**自动结论**：占协商速率的百分比、重传次数；丢包超过 1% 或有整秒停滞会变黄/标红。
- 再下面是重传 / 丢包 / 抖动 / 协商占比四个指标。
- 如果历史里有**上一次同模式、同参数**的测试，会多一行「上次「客厅」710 → 本次 728 Mb/s（+2.5%）」。
- 底部三个按钮：**再测一次**（同参数重跑）、**连测 3 次**（自动跑 3 轮，最后给中位数和区间）、
  **分享**（拉起系统分享，发文本给微信/邮件都行）。
- 右上角「加标签」可以给刚才这次补一个标签，写回历史。

**标签**：「运行」卡片最上面有一个「本次标签」输入框（例如 `客厅`、`换信道后`），
开始前填好，结果卡、历史列表和报告里都能对上号；不填也能测，历史里就用时间当标题。

**连测 3 次**：点结果卡上的「连测 3 次」，会按当前参数连续跑 3 轮（每轮之间停 1 秒），
最后一行给出 3 次的中位数和最低/最高。中途点「停止」会取消后面的轮次。

**顶栏运行状态**：不管当前停在哪个页签，顶栏都会显示「WiFi · 打流中 00:07」或
「WiFi · 服务端就绪」，切页不会误以为测试停了。

**日志能上下滑**：日志框本身就能滑。新行进来时如果视口本来就贴在底部，会自动跟着滚；
你手动往上翻看历史，它就不抢你的位置。要看更早的可以点「全屏」，或者去历史记录里翻。

**右上角「⋯」菜单**：顶栏标题右边有个「⋯」，点开两项——

- **查看历史记录**：每次打流、每次当服务端都会留一条，命名是「模式 · 时间」，
  例如 `WiFi · 2026-11-03 12:30:45`、`热点 · 2026-11-03 09:12:07`、`P2P · 2026-11-02 16:40:11`。
  服务端的记录会带「· 接收」，例如 `WiFi · 接收 · 2026-11-03 12:38:44`。
  **填了标签的记录，列表里优先显示标签**，下面一行带时间、模式、速率。
  点开能看到结果卡（主速率、统计、结论、与上次同参数对比）、发起端设备信息、概要、结果包大小，
  以及**那次运行的完整日志**；底部有「复制日志」「打开全屏」「分享摘要」。
  详情页的「标签」一行可以直接加/改标签。
  最多留 50 条，超了自动淘汰最旧的；每条右侧有「删除」。
  需要重新发给 PC 时，回主界面点「重传上次结果」。
- **设置结果回传 PC**：PC 端地址 + 端口就配在这里，配一次三页通用。以前每个页面都重复摆一份
  「结果回传」，现在收进这个菜单了。

**历史记录存在手机上哪里**：历史页顶部有一张「数据保存在手机上哪里」的卡片，直接写出两个路径：

| 位置 | 路径 | 用途 |
| --- | --- | --- |
| 手机上的位置 | `/data/user/0/com.wifitput.android/files/history` | App 自己的权威副本，删 App 就没了 |
| USB 可见位置 | `/storage/emulated/0/Android/data/com.wifitput.android/files/history` | 每次保存/删除后自动镜像一份，电脑用 adb 直接拉这里 |

- 卡片上的「立即同步到 USB 可见目录」可以手动再镜像一次，成功会提示「已同步 N 条到 USB 可见目录」。
- 为什么要镜像：release 包的私有目录电脑上拉不到（`run-as: package not debuggable`），
  所以必须落一份到外部存储。这个目录是 App 专属的，卸载 App 会跟着清掉，属于正常现象。
- 路径做成了**可选中复制**（等宽字体），排查时可以长按复制。

**灭屏照样跑**：点「开始打流」或「当服务端」后 App 会起一个前台服务，同时拿 CPU 唤醒锁
和 WiFi 高性能锁，所以按电源键灭屏、切到别的 App 都不影响打流。测完记得让它自己停，
或者在「运行」里点「停止」。

日志是**攒批刷新**的：120 毫秒内的多行合并成一次写入，不再每来一行就重排整个控件。
所以四流跑起来时每秒 5 行（4 条流 + 1 条 SUM）会连续滚动，不会出现「中间几秒没显示、
突然跳一段」的卡顿。

## 热点页 / P2P 页

切到「热点」或「P2P」Tab，参数区下面会多出一块专用按钮。

**热点**（一台开热点，另一台连上它打流）：

热点在**系统设置里开**，App 不代开。原因是 App 内能开的只有 `LocalOnlyHotspot`——
射频确实是真的（实测另一台能连上、能跑到 138 Mb/s），但它不共享外网，
系统热点开关也不会变成已开启，另一台手机在 WLAN 列表里看到的也不是你平时那套热点配置。
为了让你看到、连上的就是系统那个热点，这块改成引导：

- 开热点这台：点「去系统设置开热点」→ 跳到系统的「便携式热点」页 → 打开开关。
  按返回键回到 App，它会在 `onResume` 里自动重新检测一次，卡片上出现绿字
  「已检测到本机热点：本机地址 10.66.2.84（wlan1）」。
- 也可以随时点「重新检测」手动刷新。没开热点时卡片是灰字提示，不会误报。
- 连热点这台：去系统设置 → WLAN，选对方的热点名、输密码连上，再回 App 点「扫描对端」。
- 检测办法：扫网卡里 `wlan1` / `ap*` / `swlan*` / `softap*` 这类 SoftAp 名字，
  再退一步看有没有 `192.168.43.x` 这种老机型热点网段，两条都不中才算「没开」。
- 个别机型（尤其开了运营商定制策略的）会限制同时开热点和连 WiFi，此时先在系统里关掉 WiFi。

**P2P**（Wi-Fi Direct 组网，两台手机点对点，不需要路由器）：

- 正常用法只有一步：**出码那台点「我的投屏码」，另一台点「扫码直连」扫它**。
  出码这台会自动先当群主建组、把组网信息编进二维码；扫码那台扫到之后自动搜对端、自动连上组，
  并把群主地址填进输入框。全程不用手输任何东西。
- 出码页、扫码页都是**竖屏**（和手机日常握姿一致，单手举着对码更稳）。
- 出码这台的日志会打出 `OK 投屏码已生成，群主地址 192.168.49.1，设备名 xxx`；
  扫码那台会依次打出 `-- 投屏码指向 xxx，正在搜对端准备组网…` → `OK 已按投屏码填好对端地址：192.168.49.1:5201`。
- 「出码这台」自动成为群主，地址固定 `192.168.49.1`；扫码那台是加入方，拿到 `192.168.49.x`。
- **手动组网（备用）**：投屏码那套走不通时（例如对端没装这个 App、或者现场 P2P 设备太多），
  展开这张卡片还有「组建群组 / 搜索设备 / 退出群组」三个老按钮。
  「搜索设备」只列附近所有 P2P 设备（不只是装了本 App 的），点一条就连。
- 扫码要相机权限；不给也能用「扫描对端」和手工填地址。
- 收尾：点「退出群组」解散。**上一次留下的空群组会拖慢下一次出码**，App 会在出码前先自动清一遍并提示「正在清理残留群组…」。

**二维码里装的是什么**：`wifitput://peer?ip=…&port=…&name=…`。

- `ip`/`port` 是群主地址和端口，扫码方直接拿来填输入框。
- `name` 是出码那台的设备名（如 `Infinix NOTE 60 Pro`），扫码方靠它在搜到的 P2P 列表里认人。
  **故意不用 MAC**：Android 12 起 `WifiP2pDevice.deviceAddress` 对普通 App 一律返回
  `02:00:00:00:00:00`（参考的投屏 App 自己拿到的也是这个值），按 MAC 直连不可能成功。


## 结果推给 PC 端

PC 上跑 `PC端工具\启动.bat`，窗口顶部会显示一行地址，形如
`http://10.216.9.198:8737/api/v1/results`。

手机与 PC 在**同一个局域网**时：点 App 右上角「⋯ → 设置结果回传 PC」，把这行里的
`10.216.9.198` 填进「PC 端地址」框，端口保持 8737，点「保存」。
手机与 PC 不在同一网段、只用 USB 连着时：先

```
adb reverse tcp:8737 tcp:8737
```

然后把手机里的地址填 `127.0.0.1`、端口 `8737`。

填好之后打流结束会自动上传；已经跑完的结果可以点「重传上次结果」重传，也可以在历史记录里
点那条记录的「发送」。不填地址也能测，结果留在手机里。

## 用 USB 把历史记录导出到电脑

上面那条是「手机主动推」，要两侧同一个局域网。**没有网络、只有一根数据线**时走这条：

1. 手机用 USB 连电脑，打开开发者选项里的「USB 调试」，手机上弹出的授权提示点「允许」。
2. PC 端打开 PC端工具\启动.bat → 「收结果」页 → 「从手机导出（USB）」卡片。
3. 「刷新设备」下拉框里会列出插着的手机（形如 16306705AY100050 Infinix X6878），选中后点「从手机导出」。
4. 电脑会拉走手机上所有历史记录，逐条落盘出报告，日志里提示「USB 导出：… 导入 N 条，跳过 N 条」。

细节：

- 原始 JSON 留在 PC端工具\手机导出\序列号-时间戳\ 下，导坏了能回看原始文件。
- 一次导出会把手机里**全部**历史都拉走，不能挑某几条。
- 手机端不用做任何操作 —— 上面那条 USB 可见路径就是给电脑拉的。
- 服务端记录（role=server）在手机上本来就没有结果包，PC 端会**按日志里的逐秒行还原**出一份最小报告，
  所以这种报告只有**接收侧**速率，没有「发送端」那一列。这是物理限制，不是 bug。
- 唯独「对端根本没打上来」的那几次（日志只有三行启动信息、没有一行数据）会被跳过。
  没有数据就不还原，PC 端不会替你编一个速率出来。
- 连着多台手机时用下拉框选，不用拔线。

## 三条硬性限制

1. **只支持 arm64-v8a**（Android 8.0 / API 26 及以上）。x86 模拟器装不了，跑不起来。
2. **iperf3 必须留在 App 自己的 nativeLibraryDir 里跑**。App 的文件目录是 noexec 分区，把二进制拷出来放到别处执行会直接被系统拒绝；另外静态 musl 版 iperf3 会被 App 自己的 seccomp 判成非法系统调用（退出码 159）。现在打进去的是 Termux 的动态链接版，`libiperf3.so` / `libiperf.so` / `libcrypto.so` 三个文件互相用 `$ORIGIN` 找依赖，**升级时三个要一起换**。
3. **首次启动要授权**：定位（Android 10 以下读 SSID 必需）、附近设备（Android 12+ 读 WiFi 信息必需）、通知（前台服务要显示常驻通知）。拒绝后打流仍能跑，但设备信息、对端发现会残缺。

## 自己重新打包

上一级 `AndroidApp\` 是完整 Gradle 工程，工具链（JDK 17 / Gradle 8.7 / build-tools 34 / platform 34）已内置在 `_android_sdk\`。

```
cd AndroidApp
打包apk.bat
```

脚本会设好 `JAVA_HOME` / `ANDROID_HOME` / `GRADLE_USER_HOME` / `ANDROID_USER_HOME`（后两个必须指到工作区内，否则 Gradle 会去写 `%USERPROFILE%` 被系统拒绝），然后 `assembleDebug` + `assembleRelease`，产物拷到 `APK\`。可以传第一个参数换输出目录：

```
打包apk.bat D:\some\where
```

全量首次约 4 分钟，改一两个 java 文件后增量约 30-40 秒。

## 已知限制

- PC 端「出报告」用的是命令行工具里的 `report.py`；手机端只负责产出结果包，不做本地报告渲染。
- 扫码直连靠**设备名**在 P2P 列表里认人（Android 12 起 App 拿不到真实 P2P MAC，只能拿到打码的 `02:00:00:00:00:00`）。所以：出码这台如果**改了系统里的设备名**，扫码方就可能认不到；现场如果几十台 P2P 设备同名，也可能认错。这两种情况展开「手动组网（备用）」点「搜索设备」挑一台即可。
- 首次扫码后建组一般 3~10 秒；如果上一次留下的空群组没清干净，点「我的投屏码」会先自动清一遍（日志提示「正在清理残留群组…」），仍失败就展开手动组网点一次「退出群组」再来。
- 反向打流（`-R`）时，客户端侧的「发送端」行取自服务端上报的 `Server output:` 段，这一段的记录不写进逐秒明细，只用来取速率。
- App 不采集屏幕亮灭对比、不做长时间稳定性测试 —— 那是命令行工具的能力，手机上做这些会受系统省电策略干扰。
