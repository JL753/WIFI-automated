# WiFi 打流 · PC 接收器

手机端（Android App）打完流，把结果推给这台电脑，这里负责接收、落盘、出报告。
它自己不发起打流 —— 打流全在手机上。

---

## 一、怎么启动

双击 `启动.bat`。

需要这台电脑有 Python 3.8 以上。界面库 PySide6 已经随包放在 `vendor\` 里，
不用 pip 装。

第一次可以先跑自检：

```
启动.bat --selftest
```

全部正常会打印 `自检结果：全部通过`，否则逐条列出 `[!!]` 的问题。

## 二、三个页面

### 1. 收结果

- 打开后如果设置里勾了「启动时自动开始接收」，会直接监听端口（默认 8737）。
- 页面上会打印手机该访问的地址，形如
  `http://10.216.9.198:8737/api/v1/results`。
- 手机和电脑必须在同一个局域网（同一个 WiFi 或同一个热点）。
- 收到结果后：目录里生成四个文件，下面表格多一行，双击那一行直接打开报告。
- `模拟发送` 按钮会在本机自己造一份示例结果 POST 给自己，用来验证
  「接收 → 落盘 → 出报告」整条链路，不需要手机。

**没有网络、只有一根 USB 线**时，用下面的「从手机导出（USB）」：

- 手机用 USB 连电脑 → 打开开发者选项的「USB 调试」→ 手机上弹出的「允许 USB 调试」点允许。
- 点「刷新设备」，下拉框里列出插着的手机（形如 `16306705AY100050`）。
- 选一台 → 点「从手机导出」。工具用 adb 把手机外部存储里的
  `Android/data/com.wifitput.android/files/history` 整个拉下来，逐条落盘出报告，
  最后提示「导入了 N 条，跳过 N 条」。
- 原始 JSON 留在 `手机导出\<序列号>-<时间戳>\` 下，导坏了能回看原始文件。
- 拉取走的是 `adb pull`，而 **adb 不认识含中文的目标路径**（会报
  `Illegal byte sequence`），所以拉的过程是两段式：先拉到纯 ASCII 的临时目录，
  再用 Python 拷贝进 `手机导出\`。这层你不用管，只是别把 `%TEMP%` 指到中文路径上。
- **服务端记录**（手机当服务端时留下的）在手机上本来就没有结果包，
  工具会按日志里的逐秒行还原出一份最小报告：只有**接收侧**速率，
  「发送端」那列是 `--`。这是服务端视角的物理限制，不是导入失败。
- 少数服务端记录会被**跳过**：那次对端没打上来，日志里只有三行启动信息、
  一行数据都没有。这种情况不还原 —— 没有数据就是没有数据，工具不会替你编一个速率。
  跳过几条，弹窗里会写清楚。

> 底部日志栏和上面的页面之间那条分隔条可以上下拖，想多看日志就往上拖。
> 拖完的宽度记在 `配置.json` 的 `split_sizes` 里，下次打开还是这个比例；
> 在「设置」里点「恢复默认」会连日志栏比例一起还原。

### 2. 出报告

- 左边列出 `输出\` 下所有含 `汇总.json` 的运行目录，右边直接预览 Markdown 报告。
- `导入结果包 JSON…` 可以手工导入一个手机导出的结果包，效果和接收一样。
- `打包成 zip` 把整个运行目录压成一个 zip，方便发给别人。

### 3. 设置

| 项 | 说明 |
| --- | --- |
| 监听端口 | 默认 8737；被占用时启动接收会提示换一个 |
| 输出目录 | 留空 = 用 `输出\`；填别的目录必须已存在 |
| 启动时自动开始接收 | 关掉就得每次手点「启动接收」 |

下面的「环境自检」实时显示 Python / PySide6 / 报告模块 / 本机地址 / 端口 /
输出目录可写性，出问题时先看这里。

设置保存在 `配置.json`，删掉它就恢复默认。

## 三、输出的文件

每次收到一份结果，在输出目录下建一个时间戳目录，里面：

| 文件 | 内容 |
| --- | --- |
| `逐秒明细.csv` | UTF-8 BOM + CRLF，16 列，Excel 直接打开不乱码 |
| `汇总.json` | 结构化全量数据（设备信息、每项统计、逐秒记录） |
| `测试报告.md` | 六节可读报告：结论摘要 / 测试参数 / 设备信息 / 测试结果 / 亮灭屏对比 / 异常与提示 |
| `原始输出_<测试项>.txt` | iperf3 原样输出，出问题时给人看这个 |

CSV 的 16 列和命令行版 `WiFi吞吐量测试工具` 完全一致，报告渲染也直接复用它的
`report.py`（同盘存在 `WiFi吞吐量测试工具\tools\wb\report.py` 时优先用那份，
改一处两边都变；找不到才用 `pcapp\_vendor_report.py` 的副本）。

## 四、手机端怎么对接

协议见同目录 `协议说明.md`。两个接口：

- `GET /api/v1/ping` — 探活，手机端「扫描电脑」用这个。
- `POST /api/v1/results` — 推一份结果包（UTF-8 JSON）。

手机上装同级的 `APK\WiFiTput.apk`，在 App 的「结果回传」里填这台电脑显示的地址。

**两条路，看手机和电脑在不在同一个局域网**：

1. **同一个 WiFi / 同一个热点** —— 直接填接收页上显示的那行 IP，比如 `10.216.9.198`，端口 8737。
2. **不在同一网段，只有 USB 线** —— 先用 adb 把手机的 8737 反向映射到电脑，再把手机里的地址填成 `127.0.0.1`：
   ```
   adb reverse tcp:8737 tcp:8737
   ```
   `adb reverse --list` 能看到 `UsbFfs tcp:8737 tcp:8737` 就说明通了。拔线后映射失效，要重设。

把 `输出\示例\手机回传_TCP反向UDP反向\` 是手机真机回传的一份实际结果（`20261030_202543` 那次，TCP 反向 + UDP 反向），
可以拿来对照格式。

## 五、目录结构

```
PC端工具\
├─ 启动.bat            入口（找 Python → 设环境变量 → 跑 main.py）
├─ main.py             入口与 --selftest 自检
├─ 使用说明.md
├─ 协议说明.md         手机端对接协议
├─ vendor\             PySide6 6.12.0 + shiboken6（约 225 MB，别删）
├─ pcapp\
│   ├─ paths.py        路径（vendor / 输出 / 配置 / report.py 位置）
│   ├─ protocol.py     结果包 schema 校验 + 示例包
│   ├─ receiver.py     HTTP 接收服务（后台线程）
│   ├─ reports.py      调 report.py 落盘四个文件
│   ├─ store.py        已接收索引 + 配置读写
│   ├─ pack.py         目录打 zip
│   ├─ usbexport.py     从手机导出（adb 设备探测 / 拉取历史 / 还原服务端记录）
│   ├─ context.py      跨线程信号总线 + 运行时状态
│   ├─ _vendor_report.py  报告模块兜底副本
│   └─ ui\             三个 Tab + 主窗口
├─ 输出\              每次运行一个时间戳目录
├─ 手机导出\          从手机拉的原始历史 JSON（序列号-时间戳）
└─ 配置.json          设置（自动生成）
```

## 六、常见问题

**双击闪一下就没了** — 在命令行里 `cd` 到这个目录再执行 `启动.bat`，能看到具体报错。

**提示 `[ERROR] Python 3.8+ was not found`** — 装 Python 并勾上
「Add python.exe to PATH」；或者把绿色版 Python 解压到 `PC端工具\python\`。

**提示 `[ERROR] PySide6 is missing in the vendor folder`** — `vendor\` 被删了或
拷漏了。整个目录重新拷一份，不要只拷 exe 和 pcapp。

**手机连不上** — 依次检查：① 手机和电脑是否同一个 WiFi（不能一个连热点一个连
公司 WiFi）；② 电脑防火墙是否拦了 8737 端口；③ 设置页「本机地址」显示的是不是
手机能 ping 通的那个网段。

**端口被占用** — 启动接收时会问要不要换端口，点「是」自动找下一个可用的。

**报告模块：不可用** — 说明既找不到 `WiFi吞吐量测试工具\tools\wb\report.py`，
`pcapp\_vendor_report.py` 也没了。把工具目录放回上一级，或恢复那个副本。

**CSV 用 Excel 打开是乱码** — 这个文件已经是 UTF-8 BOM，正常不该乱码。
如果你用别的编辑器另存过，编码就变了，重新跑一次不要动它。
